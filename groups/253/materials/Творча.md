# 🕵️ Творческое задание по C++

## Легенда

Ты — аналитик детективного агентства.
Агентство ведет расследования и хранит все улики в текстовых файлах.
Твоя задача — написать программу, которая **читает базу улик**, **анализирует их**,
**сортирует** и **создает итоговый отчет**.

---

## 📋 Условие задачи

### Входной файл: `clues.txt`

Программа читает файл `clues.txt`, в каждой строке которого записана улика в формате:

```
<категория> <описание_одним_словом> <важность>
```

**Пример строк:**
```
отпечаток перчатка 5
свидетель Иванов 8
документ договор 9
оружие нож 10
```

- Категория — одно слово (отпечаток, свидетель, документ, оружие...)
- Важность — целое число от 1 до 10

### Как получить свой `clues.txt`

Тебе выдается вспомогательная программа-генератор **[generate_clues.cpp](https://github.com/maykorablina/Cpp-course/blob/main/groups/253/materials/tvorcha_generate_file.cpp)**

**Шаг 1.** Открой файл **[generate_clues.cpp](https://github.com/maykorablina/Cpp-course/blob/main/groups/253/materials/tvorcha_generate_file.cpp)** и впиши свою фамилию в строку:

```cpp
std::string surname = "ВАША_ФАМИЛИЯ";
```

**Шаг 2.** Запусти программу. Она сгенерирует 200 уникальных строк.

> ⚠️ **Файл у каждого свой!** Одна и та же фамилия всегда дает одинаковый результат, но у всех файлы будут отличаться.

**Два способа получить `clues.txt`:**

| Способ | Когда использовать |
|---|---|
| Программа сама создает файл `clues.txt` | Если запускаешь локально или в компиляторе с поддержкой файлов |
| Скопировать вывод из консоли и вставить в новый файл `clues.txt` вручную | Если онлайн-компилятор не поддерживает запись файлов |

## 🖥️ Что должна делать программа

> 💡 **Обратите внимание:** для выполнения некоторых пунктов может потребоваться самостоятельное изучение материала — погуглите, посмотрите документацию или примеры в интернете. Это часть задания.

### Шаг 1 — Чтение данных
Прочитать файл `clues.txt` и сохранить все улики.

### Шаг 2 — Группировка по категориям
Используя `std::map`, разбить улики по категориям.
Вывести на экран все категории и количество улик в каждой.

### Шаг 3 — Уникальные категории
С помощью `std::set` вывести список всех уникальных категорий в алфавитном порядке.

### Шаг 4 — Сортировка улик
Внутри каждой категории отсортировать улики **по важности** (от большей к меньшей)
с помощью **сортировки пузырьком** или **сортировки вставками** (на выбор).

> ⚠️ **Важно:** сортировку нужно написать **самостоятельно** — в виде отдельной функции с циклами.
> Использование `std::sort`, `std::stable_sort` и любых других встроенных функций сортировки **запрещено**.
> Функция должна принимать `vector` и сортировать его на месте.

### Шаг 5 — Рекурсивный поиск
Написать **рекурсивную функцию**, которая ищет улику с максимальной важностью
в массиве (без использования `max_element`):

```cpp
int findMax(vector<int>& vals, int index);
```

### Шаг 6 — Итоговый отчет
Записать в файл `report.txt` следующее:
- Общее количество улик
- Список категорий и количество улик в каждой
- Самая важная улика (описание + важность)
- Отсортированный список всех улик (от самой важной к наименее важной)
- Средняя важность улик по каждой категории
- Улики из категории, выбранной пользователем

### Шаг 7 — Поиск по категории
Спросить у пользователя название категории и вывести только улики из нее (отсортированные, по важности).
Результат записывается в `report.txt`.

### Шаг 8 — Средняя важность
Подсчитать среднюю важность улик в каждой категории и вывести на экран.
Результат записывается в `report.txt`.

Уникальные категории (алфавитный порядок):
  документ, отпечаток, оружие, свидетель

=== Топ улик по категориям ===
[документ]
  1. договор (важность: 9)

  3. письмо  (важность: 7)

[отпечаток]
  1. перчатка (важность: 5)
  2. стакан   (важность: 3)

## 📌 Дополнительное задание

Реализовать **вторую сортировку** — ту, которую ты **не использовал** в шаге 4
(если выбрал пузырек — реализуй вставки, и наоборот).
Отсортируй тот же набор данных обоими алгоритмами и сравни, **какой отработал быстрее**
(подсчитай количество итераций или перестановок).

Результат сравнения (с числами и выводом) должен быть оформлен **в отчете-документе** — в виде скриншота вывода программы и краткого письменного вывода.

## 📝 Требования к отчету

Отчет сдается **в виде документа в удобном для вас формате** (PDF, Word или Google Docs) и содержит:

| # | Что включить |
|---|---|
| 1 | Скриншот файла `clues.txt` |
| 2 | Скриншоты кода (весь код, по частям) с пояснениями |
| 3 | **Скриншот обеих функций сортировки** с объяснением алгоритма каждой |
| 4 | Скриншот вывода программы: сравнение двух сортировок (сколько итераций/перестановок у каждой) |
| 5 | Скриншот вывода в консоль |
| 6 | Скриншот файла `report.txt` |
| 7 | Краткий письменный вывод: какой алгоритм оказался эффективнее и почему |
